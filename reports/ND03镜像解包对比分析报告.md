## 一、核心结论

### 1.1 原版固件：全文件加密，无法通过"去签名头"还原

| 文件 | 熵值 | 标准魔术字 | 结论 |
|---|---|---|---|
| rawprogram0/1/2.xml | — | 无 `<?xml` | 全加密 |
| patch0.xml | — | 无 `<?xml` | 全加密 |
| abl.elf | 7.81 | 无 `ELF` (7F454C46) | 全加密 |
| vbmeta.img | 7.98 | 无 `AVB0` (41564230) | 全加密 |
| vbmeta_system.img | 7.95 | 无 `AVB0` | 全加密 |
| boot.img | — | 无 `ANDROID!` | 全加密 |
| super_1~5.img | — | 无 sparse 魔术字(3AFF26ED) | 带高通签名头 |
| misc.mbn | — | — | 带高通签名头 |

**关键发现**：原版固件中所有关键镜像都是**全文件加密**（不只是32字节签名头），熵值接近8.0（AES密文特征）。作者的标准格式镜像只能来自：
- 运行时设备 dump（EDL/Firehose 读取已解密分区）
- 持有厂商解密工具/密钥
- 从其他未加密渠道获取

### 1.2 作者解锁方案：Magisk + 自定义AVB签名 + 强制进Fastboot

作者的完整技术链路：

```
原版加密固件 → 解密获取标准格式镜像
    │
    ├─ boot.img → Magisk修补（关闭avb/verity，注入root）
    ├─ vbmeta.img → 自定义RSA4096密钥重新签名
    ├─ vbmeta_system.img → 同上
    ├─ abl.img → 解密为标准ELF（可能含patch）
    ├─ super.img → 转为非sparse原始镜像（可能修改system）
    └─ misc.img → 写入"boot-fastboot"（13字节，强制进fastboot）
    │
    ▼
明文rawprogram0.xml（仅刷6个分区到_a槽位）
    │
    ▼
QPST/QFIL + 工程Firehose → EDL 9008 刷写
```

### 2.2 kernel 命令行（cmdline）关键参数

```

```

**`buildvariant=userdebug`** 表示作者使用的是 userdebug 版本的 boot（允许 adb root、关闭部分安全限制），而不是原版的 user 版本。

### 2.3 ramdisk 文件清单

```
  .rmlist               ← Magisk清理列表

    magisk32.xz         ← Magisk 32位二进制（96KB）

```

### 2.4 Magisk 配置（backup/.magisk）

```

KEEPVERITY=false          ← 关闭dm-verity

PATCHVBMETAFLAG=false
RECOVERYMODE=false
SHA1=7a72acecd1e34d30cbc6139d1e9b95c94f567773
```

### 2.5 fstab.qcom 修改对比

**原版（backup/fstab.qcom）**：
```
system    /system    ext4  ro,barrier=1,discard  wait,slotselect,avb=vbmeta_system,logical,first_stage_mount,avb_keys=/avb/q-gsi.avbpubkey:/avb/r-gsi.avbpubkey:/avb/s-gsi.avbpubkey
vendor    /vendor    ext4  ro,barrier=1,discard  wait,slotselect,avb,logical,first_stage_mount
product   /product   ext4  ro,barrier=1,discard  wait,slotselect,avb=vbmeta_system,logical,first_stage_mount
system_ext /system_ext ext4 ro,barrier=1,discard  wait,slotselect,avb=vbmeta_system,logical,first_stage_mount
```

**作者修改后（fstab.qcom）**：
```
system    /system    ext4  ro,barrier=1,discard  wait,slotselect,logical,first_stage_mount
vendor    /vendor    ext4  ro,barrier=1,discard  wait,slotselect,logical,first_stage_mount
product   /product   ext4  ro,barrier=1,discard  wait,slotselect,logical,first_stage_mount
system_ext /system_ext ext4 ro,barrier=1,discard  wait,slotselect,logical,first_stage_mount
```

**修改内容**：所有4个系统分区的 **`avb` 和 `avb=vbmeta_system` 标志被移除**，同时移除了 `avb_keys=` 公钥路径引用。这意味着内核挂载这些分区时不再进行 AVB 校验。

## 三、vbmeta.img 深度分析

### 3.1 原版 vs 作者

| 维度 | 原版 vbmeta.img | 作者 vbmeta.img |
|---|---|---|
| 大小 | 8,192 字节 | 65,536 字节 |
| 格式 | 全加密（无AVB0） | 标准 AVB0（大端序） |
| algorithm_type | — | **2 = SHA256_RSA4096** |
| flags | — | **0**（verification+verity 形式上开启） |
| 签名 | — | 有（512字节） |
| 公钥 | — | 有（1032字节自定义公钥） |
| rollback_index | — | 0 |

### 3.2 关键分析

作者**没有用 `--disable-verification` 关闭AVB**，而是：
1. 生成自己的 RSA4096 密钥对
2. 用私钥对 vbmeta 镜像签名
3. 将公钥嵌入 vbmeta 镜像

这意味着要让这个 vbmeta 通过启动校验，必须满足：
- **abl 中的 AVB 根公钥被替换为作者的公钥**，或
- **abl 中的 AVB 校验逻辑被 patch（跳过签名验证）**

由于原版 abl 是加密的无法直接对比，作者 abl 是否被 patch 需要进一步逆向确认。

## 四、misc.img 分析

| 维度 | 值 |
|---|---|
| 大小 | **13 字节** |
| 十六进制 | `62 6F 6F 74 2D 66 61 73 74 62 6F 6F 74` |
| ASCII | **`boot-fastboot`** |

**技术含义**：这是高通 Android 设备 misc 分区的标准启动命令。bootloader（abl）启动时读取 misc 分区，如果开头是 `boot-fastboot`，设备会**直接进入 fastboot 模式**。

**作用**：小天才手表没有方便的按键组合进入 fastboot，作者通过此命令让设备刷完后自动进入 fastboot。

|---|---|---|

| 架构 | — | ARM（EM_ARM=0x28） |
| 入口点 | — | 0x9FA00000 |

**分析**：
- 作者 abl.img 是解密后的标准 ARM ELF，被零填充到 abl 分区大小（1MB）
- 由于原版全加密，**无法直接字节对比判断 abl 是否被 patch**

- ramdisk 中的 AVB 公钥（q-gsi/r-gsi/s-gsi）仍然保留，但 fstab 中已移除 avb_keys 引用

### 6.4 新版 LpExtent 结构修正

在 major=10 的新版 LP 格式中，`LpExtent` 的 `physical_sector` 是 **4字节在偏移12**（不是旧版的8字节在偏移16）：
```
+0  num_sectors (8字节)
+8  target_type (4字节)
+12 physical_sector (4字节)  ← 关键修正！
+16 保留/填充 (8字节)
```
phys_offset = physical_sector × 512

## 八、与"家长验证"问题的关联分析

用户之前提到：解锁BL后仍弹出家长验证。基于本分析：

### 8.1 作者已经做的处理
1. **Magisk root**：boot.img 已注入 Magisk，获得 root 权限
2. **关闭 AVB/dm-verity**：fstab 移除所有 avb 标志，可以自由修改 system 分区
3. **userdebug 版本**：buildvariant=userdebug，允许 adb root
4. **super.img 被整体替换**：作者可能已经在 system 分区中删除/修改了家长验证相关组件

### 8.2 为什么还可能弹出家长验证
1. **家长验证逻辑可能不在 system 分区**：
   - 可能在 vendor 分区的私有守护进程中
   - 可能在内核模块中
   - 可能在 persist 分区的持久化数据中
2. **云端校验**：设备联网后，小天才后端 API 根据设备 SN 查询绑定状态，下发验证要求
3. **QFPROM 硬件绑定**：设备 SN 烧录在芯片一次性可编程区域，无法擦除，云端据此识别设备

### 8.3 后续分析方向
1. 挂载 system_a.img / vendor_a.img，搜索家长验证相关包名/服务/so库
2. 检查 persist 分区是否保存绑定状态
3. 抓 logcat 定位家长验证弹窗的触发进程和调用链
4. 用 Magisk 模块（如 LSPosed）hook 家长验证相关 API
